# Hint Lock — Technical Plan for Codex
Date: 2026-05-02

---

## Objective

Lock the Teacher Hints + Paper Pattern panel once the user saves or explicitly skips it. The button should switch to a "locked" visual state (same pattern as Syllabus / Exam Scope buttons). The user can still re-open and edit, matching the UX contract already established for locked items. A separate "Skip" path must also be implemented.

---

## File

All changes are in ONE file only:

**`app/dev-test/page.tsx`**

Do NOT touch any API routes, DB schema, trigger tasks, lib files, or any other file.

---

## Current State

### Data shape (loaded per subject in `loadSubjects`)
```
teacherHints: parsedHints.teacherHints || null   // string | null
paperPattern: parsedHints.paperPattern || null   // string | null
hintConfidence: hintsData?.confidence || null    // string | null
```

A subject has hints if `subject.teacherHints !== null` OR `subject.paperPattern !== null`.

### State variables (already exist)
- `expandedHintSubjectId` — which subject's hints panel is open
- `hintsText`, `paperPatternText`, `confidenceLevel` — controlled form state
- `isSavingHints`, `isLoadingHints` — async state
- `subject.config` — a JSON object already used for `pyqs_skipped`

### The button (line ~2774)
Currently: always shows "📝 Hints + Pattern", amber toggle button. No lock state.

### The save handler (`saveHintsInline`, line ~667)
Saves to `teacher_hints` table via `/api/subjects/teacher-hints`. On success, updates the in-memory subject with new hint values.

## Implementation

### Step 1 — Add `hints_skipped` to subject config tracking (local state only)

In the subject data object returned by `loadSubjects` (around line 492), add:

```
hintsLocked: (parsedHints.teacherHints !== null || parsedHints.paperPattern !== null) || subject.config?.hints_skipped === true
```

Add `hintsLocked: boolean` to the inferred subject shape. This is a derived boolean — `true` when either hints are saved OR user has explicitly skipped.

### Step 2 — Update the "📝 Hints + Pattern" button (line ~2774)

Derive `hintsLocked` from subject at the top of the subject render loop (same as how `isSyllabusProcessing` is derived):

```ts
const hintsLocked = subject.hintsLocked === true
```

Replace the current single button with a conditional:

**When `hintsLocked === false` (not yet set):**
- Show: `📝 Add Hints + Pattern` — same amber tone as current
- Clicking opens the panel as today

**When `hintsLocked === true` (already saved or skipped):**
- Show: `🔒 Hints Locked` — use the green locked style matching the Syllabus locked button:
  ```
  bg-green-900/30 border-green-700 text-green-400 cursor-pointer
  ```
  (NOT `cursor-not-allowed` — locked hints can still be re-edited)
- Clicking opens the panel in edit mode (same toggle behaviour, no change to `toggleHintsInline`)
- Title inside the open panel changes to "Edit Teacher Hints + Paper Pattern"

### Step 3 — Add "Skip — No Hints" button

Below the hints button row (or inside the panel footer, adjacent to "Save Both"), add a **"Skip — No Hints"** action.

**Placement:** In the inline hints panel footer (`div.flex.justify-end.gap-3` at line ~3028), add a third button to the left side:

```
[Skip — No Hints]    [Cancel]    [Save Both →]
```

**Behaviour:**
- Calls `saveSubjectConfig(subject.id, { hints_skipped: true })`
- Sets `hintsLocked: true` on the in-memory subject (via `setSubjects`)
- Closes the panel (`setExpandedHintSubjectId(null)`)
- Disabled if `isSavingHints` is true
- Style: muted, e.g. `text-xs text-slate-500 hover:text-slate-300 underline transition-colors`

Do NOT call `saveHintsInline` from skip. Skip only writes to subject config.

### Step 4 — Update `saveHintsInline` success handler (line ~686)

After a successful save, update the subject in `setSubjects` to also set `hintsLocked: true`:

```ts
setSubjects(prev =>
  prev.map(s =>
    s.id === subjectId
      ? { ...s, teacherHints: hintsText.trim() || null, paperPattern: paperPatternText.trim() || null, hintConfidence: confidenceLevel, hintsLocked: true }
      : s
  )
)
```

Remove the `alert("Teacher hints and paper pattern saved successfully!")` — replace with a non-blocking experience (panel just closes, button visually locks).

### Step 5 — Update `loadSubjects` data shape (line ~492)

In the returned subject object, compute `hintsLocked`:

```ts
hintsLocked:
  !!(parsedHints.teacherHints || parsedHints.paperPattern) ||
  subject.config?.hints_skipped === true,
```

## Constraints — DO NOT touch

- Any API route files (`/api/subjects/teacher-hints`, `/api/subjects/config`, etc.)

- Any trigger task files

## Done Criteria

1. Button shows `📝 Add Hints + Pattern` when no hints and not skipped
2. Button shows `🔒 Hints Locked` (green, still clickable) after save or skip
3. Locked button still opens the panel for editing
4. "Skip — No Hints" button in the panel footer writes `hints_skipped: true` to config and locks the button
5. Successful save closes the panel and locks the button without an `alert()`
6. Page refresh correctly re-derives lock state from DB data (`loadSubjects`)
