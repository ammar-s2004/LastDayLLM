# Notes: 150-Page Upload Limit & Natural Output Scaling

**Objective**: Enforce a 150-page hard limit on notes uploads to prevent abuse, while relying on the unconditional `maxOutputTokens = 65536` to let the AI naturally scale its output based on document density.

---

## Architectural Decision

In a previous plan, we considered a complex token budget formula based on page counts. However, as noted by Ammar, page count is a poor proxy for content density (a sparse 120-page doc vs. a dense 40-page doc).

Furthermore, `maxOutputTokens` is a *ceiling*, not a target. The AI will naturally stop generating tokens when it has fully extracted the document. By giving it the maximum allowed ceiling (`65536`), we ensure:
1. Dense documents are never artificially truncated.
2. Sparse documents naturally produce fewer tokens without padding.

Therefore, the pipeline requires only two things:
1. **The Maximum Ceiling**: `maxOutputTokens` must be unconditionally set to `65536` for all models. *(Note: This was already completed in a previous step).*
2. **The Upload Guard**: A hard 150-page limit must be enforced at the `/api/notes-v2/upload/route.ts` boundary to prevent users from uploading massive PDFs (e.g., 500-page textbooks) that hammer the system.

This plan focuses entirely on implementing the Upload Guard.

---

## Phase 1 — Enforce 150-Page Upload Guard

### MODIFY `app/api/notes-v2/upload/route.ts`

**Goal**: Reject PDFs exceeding 150 pages before any storage or API cost is incurred.

**Steps**:

1.  **Define the Constant**: Add `MAX_NOTES_PDF_PAGES = 150` at the top of the file alongside `MAX_FILE_SIZE`.
2.  **Intercept the Upload**: Immediately after `const pageCount = pdfDoc.getPageCount();` (around line 178) and *before* the `Promise.allSettled` block that uploads the file to Supabase and Google File API.
3.  **Return 400 Error**: If `pageCount > MAX_NOTES_PDF_PAGES`, return a `NextResponse.json` with a 400 status.

**Code to Insert**:
```typescript
const MAX_NOTES_PDF_PAGES = 150;

// ... inside POST handler, after parsing the PDF ...

if (pageCount > MAX_NOTES_PDF_PAGES) {
    return NextResponse.json(
        {
            error: `PDF too long`,
            message: `This PDF has ${pageCount} pages. Maximum allowed is ${MAX_NOTES_PDF_PAGES} pages. Please split the document or upload individual chapters.`
        },
        { status: 400 }
    );
}
```

**Constraints**:
-   The error response format must match the existing error shape `{ error: string, message?: string }`.
-   Must return immediately; do NOT upload the file to Supabase or Google.
-   Do NOT touch any other validation logic (e.g., file type, file size).

**Done when**: Uploading a 151-page PDF returns a `400 Bad Request` with the `"PDF too long"` error message. Uploading a 150-page PDF proceeds normally.
